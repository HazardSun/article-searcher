## 二、崩溃修复正确性验证

**改动点**：
- `core/device_manager.py` `build_session_options()`（约 206–235 行）：将 `ORT_PARALLEL` 改为 `ORT_SEQUENTIAL`，并显式设置 `intra_op_num_threads=1`、`inter_op_num_threads=1`，强制单线程推理以修复崩溃。
- `core/onnx_engine.py` 新增 `_warmup()`（约 163–175 行），在加载后预热一次。

**验证脚本**：`verify_crashfix_vectors.py`（加载 `EmbeddingEngine`，编码 3 句中文，校验维度、L2 归一化、稳定性）。

**实测结果**：

| 校验项 | 预期 | 实测 | 结论 |
|---|---|---|---|
| 向量维度 | 512（bge-small-zh-v1.5） | `(3, 512)` | ✅ |
| L2 归一化（norm） | ≈ 1.0 | `[1.0, 1.0, 1.0]` | ✅ |
| 同输入稳定性（cosine） | ≈ 1.0 | `1.00000012` | ✅ |
| 执行后端 | onnx / CPU | `onnx \| CPUExecutionProvider` | ✅ |
| SessionOptions | 单线程 | `ORT_SEQUENTIAL, intra=1, inter=1` | ✅ |

> **结论**：单线程化仅影响推理**速度**，不改变**数值正确性**。崩溃修复未破坏向量维度、归一化与编码稳定性，语义检索结果不受影响。✅ 修复有效。

**Top 3 风险**：

1. **P1-1 / P1-2：两处 `QSize` 未导入导致 UI 渲染崩溃** —— Ctrl+K 快捷检索与相似推荐是高频交互入口，当前每次出结果必崩，严重拉低可用性。修复成本极低（补一行 import），建议**优先修复**。
